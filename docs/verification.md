## v0.2.0 grid 图库验证

真实 Safari 已显示 grid 图库、小 / 中 / 大尺寸、全部图片 / 收藏筛选和缓存进度。收藏范围的切图和 Esc 返回可用；深滚动时只挂载附近卡片，隐藏的左侧列表没有挂载卡片。缓存显示阶段、完成与待缓存数量；扫描未结束时标明「总数仍在增加」。

浏览器压力脚本为 `tests/browser/grid-scenario.js`，只允许在 localhost 的测试图片预览运行。使用 30,000 张混合横竖比例图片，新增头部图片后为 30,001 张，测试三种尺寸的连续深滚动、刷新定位、返回大图位置、收藏筛选与取消收藏、大图切换遵循收藏范围、保存查看状态，以及原图 / 缩略图 / 暂停进度显示。

本次 1280 × 577 预览测量：三档实际卡片宽度为 198 / 303 / 408 px；连续滚动最多挂载 50 张卡片，跟踪到最多 23 个存活预览 Object URL。每次滚动后等待两个动画帧的耗时 P95 为 35.5 ms；这只是本机预览测量，不是 Safari 帧率承诺。页面重新加载后恢复到 200,000 px 的原浏览位置。缓存阶段模拟只用于预览测试；保存的扫描游标存在而后台尚未恢复时，显示「等待后台恢复」。

虚拟化滚动不会逐帧遍历所有图片：每列二分查询可见范围，在动画帧内更新附近卡片。后台元数据更新会合并通知；同样的排序与尺寸不重建布局。v0.2.0 曾在离开范围时释放预览 URL，这导致回滚重新加载；v0.2.1 已改为共享缩略图内存缓存。此前两个动画帧的布局测量没有等待图片真正显示，不能作为缩略图显示速度的证据。

## v0.2.1 缩略图性能与清晰度

先前 Safari 诊断显示，缓存读取与解码之外还存在后台消息、data URL 转换和 FIFO 排队。部分缩略图过大；Safari 的 `canvas.toBlob('image/webp')` 实际回退为 PNG，原生 JPEG 编码明显更快、体积更小。这些为本机样本，不能推广为所有图片的固定耗时。

修复后，本地缓存直接只读访问，不经过后台消息、base64 或下载队列。近期缩略图按 256 MB 估算预算保留字节和解码像素，卸载卡片后保留已解码图片元素，回滚直接重新挂载。附近只预读本地资源，首次屏幕内图片优先于额外预读；缓存读取、下载、缩小和解码分开调度。旧模糊 / 过大缩略图从缓存原图重建，按 CSS 尺寸和屏幕像素密度补足像素；不透明图使用高质量 JPEG，透明图使用 PNG。已知尺寸写入元数据并在刷新时保留。

`tests/browser/thumbnail-performance.js` 使用 120 张 1024 × 1408 PNG 栅格测试原图与旧小缩略图，在 1280 × 577、2 倍屏幕像素密度下运行。12 张 408 CSS px 所需缩略图准备耗时 87 ms，输出宽度 896 px；再次访问准备为 0.1 ms，磁盘读取仍为 12 次，下载为 0 次。三档实际卡片宽度 198 / 303 / 408 px，图片均有足够的源像素。15 次滚动测试等待屏幕内图片达到所需分辨率并等待绘制帧，首次显示 P95 为 181 ms，回滚 P95 为 48 ms；回滚确认复用同一个 HTMLImageElement。透明通道、从大图返回位置均通过。该测试证明本机栅格预览行为，不代替真实 Safari 验收。

最终 30,000 张瀑布流回归仍通过：三档宽度 198 / 303 / 408 px，最多 50 张卡片，刷新锚点、大图返回、收藏筛选、缓存进度和保存 200,000 px 浏览位置正常。两个动画帧布局耗时 P95 为 35.5 ms；本次观测到的 URL 数量不是内存预算的证明，预算回收与可见资源保护由专门测试覆盖。

真实 Safari 最终测试关闭检查器后运行，在 1512 × 771 图片区域、2 倍像素密度、后台继续缓存时，三次进入 2000 / 4000 / 6000 px 的已有缓存区域，8 / 8 / 10 张屏幕内缓存图片全部显示并等待绘制帧的耗时分别为 212 / 303 / 296 ms；回滚为 82 / 6 / 33 ms，三次均复用同一 HTMLImageElement。361 CSS px 卡片使用 768 px 缩略图，超过所需 722 px，未用低分辨率预览放大替代缓存原图。已恢复测试前的尺寸与滚动位置并关闭检查器，后台缓存继续运行。

真实 Safari 样本的首访仍有超过 200 ms 的情况，不能宣称所有首访都满足 200 ms；上述为整屏而非第一张图片的耗时。旧缓存首次重新生成、图片复杂程度和后台活动会影响时间。近期回滚已避免重复磁盘读取和重新创建图片加载过程；内存资源被预算回收后，需要再次读取磁盘。全部半年图片的下载尚未完成。

`tests/browser/library-features.js` 使用 2,000 张测试图片，验证三个栏目隔离、正常大图不残留隐藏图片、隐藏当前图后切换、取消隐藏、最后一张移除后清空、卡片 / 大图收藏定位、约 200 ms 布局动画及在点击内同步发起剪贴板写入。全部图片与收藏分别保存 19,000 px 和 9,000 px，重新加载后分别恢复。额外验证连续隐藏四张图片无状态丢失、动画资源清理，以及减少动态效果时关闭布局动画。

Toast 改为随文字收缩，保留原位置，长消息最多 420 px 并换行；本机预览中「prompt 已复制」约 100 px。
